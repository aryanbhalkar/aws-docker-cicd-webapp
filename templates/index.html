End-to-end delivery

How the automated workflow operates

The pipeline transforms every approved source-code change into a tested Docker image and safely deploys it as a new ECS task behind an Application Load Balancer.

1

Code Commit

The developer commits application or infrastructure changes and pushes them to the GitHub main branch.

2

Source Trigger

GitHub App integration detects the new commit and automatically starts AWS CodePipeline.

3

Build and Test

AWS CodeBuild installs dependencies, runs pytest and creates the production Docker image.

4

Image Storage

The tested image receives a commit-based tag and is securely pushed to Amazon ECR.

5

ECS Deployment

CodePipeline updates the ECS service with a new task definition revision and Fargate task.

6

Health Validation

The ALB target group checks the health endpoint before routing production traffic to the new task.

Technology stack

AWS services used in the project

Each service has a clear responsibility, creating a modular delivery system that is easier to operate, monitor and extend.

GH

GitHub Repository

Stores the Flask source code, tests, Dockerfile and buildspec configuration. Pushes to main trigger the release workflow.

CP

AWS CodePipeline

Orchestrates the Source, Build and Deploy stages and moves artifacts safely between each stage.

CB

AWS CodeBuild

Installs dependencies, runs pytest, builds and tags the Docker image and pushes it to ECR.

ECR

Amazon ECR

Stores private container images using both the latest tag and traceable Git commit-based tags.

ECS

Amazon ECS Fargate

Runs the container without requiring EC2 server management, while the ECS service maintains the required task count.

ALB

Application Load Balancer

Provides the public application endpoint and routes HTTP traffic only to healthy ECS targets.

TG

Healthy Target Group

Registers Fargate task IP addresses and continuously evaluates the application through the health route.

CW

Amazon CloudWatch

Centralizes Gunicorn, application and CodeBuild logs for troubleshooting and operational monitoring.

IAM

AWS IAM

Grants the minimum permissions required for ECS image pulls, CodeBuild image pushes, logs and pipeline artifact access.

Pipeline execution

Source → Build → Deploy

A successful release requires all three stages to pass. A failed automated test stops the workflow before the application reaches production.

Source

Succeeded
  • GitHub via GitHub App
  • Main branch monitored
  • Source artifact generated

Build

Succeeded
  • Python dependencies installed
  • Automated pytest tests passed
  • Docker image built
  • Image pushed to ECR

Deploy

Succeeded
  • Image definitions processed
  • ECS task revision created
  • Fargate task started
  • Healthy target receives traffic
